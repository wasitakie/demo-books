# ระหว่างบรรทัด — Between the Lines

เว็บไซต์แคตตาล็อกร้านหนังสือภาษาไทย สร้างด้วย **Next.js 16 App Router, React 19 และ TypeScript** เจ้าของร้านจัดการรายการหนังสือผ่าน Google Sheets และให้เว็บไซต์อ่านข้อมูลจากฝั่งเซิร์ฟเวอร์

ค้นหาหนังสือ กรองหมวดหมู่ ดูรายละเอียด ราคา และสถานะสินค้าได้ พร้อมเปิดลิงก์สั่งซื้อหรือติดต่อร้าน เว็บไซต์ยังไม่มีตะกร้าสินค้า ระบบชำระเงิน หรือหน้าแอดมิน

## เริ่มใช้งาน

ต้องมี **Node.js 22.13.0 ขึ้นไป** และ **pnpm 10.8.1**

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

เปิด [localhost:3000](http://localhost:3000) หากมี `.env.local` อยู่แล้ว ให้แก้ไฟล์เดิมแทนการคัดลอกทับ

เมื่อยังไม่กำหนด `GOOGLE_SHEET_ID` เว็บไซต์จะแสดงหนังสือและราคาสมมติพร้อมป้ายข้อมูลตัวอย่าง และไม่เปิดรับคำสั่งซื้อจากรายการเดโม หากกำหนดชีตแล้วแต่เชื่อมต่อไม่ได้ ระบบจะรายงานข้อผิดพลาดแทนการนำข้อมูลเดโมมาแสดง

## เชื่อมต่อ Google Sheets

1. สร้าง Google Sheet แล้วนำเข้า [data/books-template.csv](data/books-template.csv) ตั้งชื่อแท็บเป็น `Books` และเปลี่ยนข้อมูลตัวอย่างเป็นหนังสือของร้าน
2. เปิด **Google Sheets API** ใน Google Cloud project สร้าง service account และ JSON key
3. แชร์ชีตให้ `client_email` ของ service account เป็น **Viewer** โดยไม่ต้องเผยแพร่ชีตสู่สาธารณะ เจ้าของร้านยังแก้ข้อมูลด้วยบัญชี Google ปกติ
4. ใส่ค่าต่อไปนี้ใน `.env.local` โดยเก็บไฟล์ JSON key ไว้นอก repository:

```dotenv
GOOGLE_SHEET_ID=your_spreadsheet_id
GOOGLE_SERVICE_ACCOUNT_EMAIL=your-service-account@your-project.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nYOUR_PRIVATE_KEY\n-----END PRIVATE KEY-----\n"
GOOGLE_SHEET_RANGE=Books!A1:Z1000
```

`GOOGLE_SHEET_ID` คือส่วนระหว่าง `/d/` และ `/edit` ใน URL ของชีต ส่วนอีเมลและ private key ใช้ค่า `client_email` และ `private_key` จาก JSON key ตามลำดับ รองรับ private key ที่ใช้ `\n` แทนการขึ้นบรรทัดใหม่

เริ่มเซิร์ฟเวอร์ใหม่หลังแก้ environment variables เมื่อแก้รายการหนังสือในชีตแล้ว เพียงโหลดหน้าเว็บใหม่เพื่ออ่านข้อมูลล่าสุด

### เลือกแท็บด้วย GID

หากชื่อแท็บเปลี่ยนบ่อย ให้ใช้เลข `gid` จาก URL ของแท็บนั้น ระบบจะค้นหาชื่อแท็บจริงให้อัตโนมัติ:

```dotenv
GOOGLE_SHEET_GID=123456789
GOOGLE_SHEET_RANGE=A1:Z1000
```

ใช้เลขของชีตจริงแทนค่าตัวอย่าง ช่วงข้อมูลต้องครอบคลุมหัวตาราง ซึ่งระบบจะค้นหาใน 10 แถวแรกของช่วงที่อ่าน ค่าเริ่มต้นอ่านถึงแถว 1000; หากมีข้อมูลมากกว่านี้ ให้ขยายช่วง

## รูปแบบข้อมูลหนังสือ

ต้องมีหัวคอลัมน์ `id`, `title`, `author`, `category` และ `price` ส่วนคอลัมน์อื่นเป็นตัวเลือก รองรับชื่อภาษาไทยตามตารางนี้ด้วย

| คอลัมน์ | ชื่อภาษาไทยที่รองรับ | วิธีกรอก |
| --- | --- | --- |
| `id` | รหัสหนังสือ | รหัสไม่ซ้ำ เช่น `book-001` |
| `title` | ชื่อหนังสือ | ชื่อที่แสดงบนเว็บไซต์ |
| `author` | ชื่อผู้แต่ง | ชื่อผู้เขียน |
| `category` | หมวดหมู่ | ใช้สร้างปุ่มกรองอัตโนมัติ; หากเว้นว่างใช้ “อื่น ๆ” |
| `price` | ราคา / ราคา (บาท) | ตัวเลขตั้งแต่ 0 รองรับเครื่องหมายคั่นหลักพัน ไม่ใส่สัญลักษณ์สกุลเงิน |
| `cover` | รูปหน้าปกหนังสือ / อัปโหลดหน้าปก | URL ภาพ HTTPS หรือลิงก์ไฟล์ภาพ Google Drive |
| `cover_approved` | อนุมัติรูปภาพ / อนุมัติแสดงลิงค์รูปภาพ | `TRUE`, `อนุมัติ` หรือ `อนุมัติแล้ว` เพื่อแสดงภาพ |
| `description` | เรื่องย่อ / รายละเอียด | เรื่องย่อหรือรายละเอียดหนังสือ |
| `buy_url` | ลิงก์สั่งซื้อ / ช่องทางสั่งซื้อ | ลิงก์ HTTPS สำหรับสั่งซื้อรายเล่ม |
| `stock` | จำนวนคงเหลือ / stock (จำนวนคงเหลือ) | จำนวนเต็มตั้งแต่ 0; ค่าว่างหรือไม่ถูกต้องแสดง “—” |
| `status` | สถานะ / status (สถานะ) | เช่น `พร้อมขาย`, `สินค้าหมด`, `พรีออเดอร์`, `หยุดจำหน่าย` |
| `available` | — | `FALSE` ปิดการสั่งซื้อ |
| `published` | published (แสดงสถานะหนังสือ) | `FALSE` ซ่อนรายการ; ค่าว่างหรือค่าอื่นแสดงรายการ |

ข้อกำหนดที่ควรทราบ:

- แถวที่ไม่มีรหัสหรือชื่อหนังสือ ราคาว่าง/ไม่ถูกต้อง/ติดลบ หรือรหัสซ้ำกับรายการที่รับไปแล้ว จะถูกข้าม
- `available=FALSE` หรือสถานะ `สินค้าหมด` / `หยุดจำหน่าย` จะปิดการสั่งซื้อ
- `stock=0` ปิดการสั่งซื้อ ยกเว้นสถานะพรีออเดอร์ที่ไม่ได้ถูกปิดด้วยเงื่อนไขข้างต้น
- หากไม่กรอก `status` ระบบจะใช้ `สินค้าหมด` เมื่อ `available=FALSE` หรือ `stock=0`; กรณีอื่นใช้ `พร้อมขาย`
- หากไม่มีข้อมูลหนังสือให้แสดง เว็บไซต์จะแสดงข้อความ “กำลังจัดชั้นหนังสือ”

ไฟล์ CSV ตัวอย่างมี `cover_approved` อยู่แล้ว ส่วน `stock` และ `status` สามารถเพิ่มภายหลังได้ ใช้หัวคอลัมน์เพียงชื่อเดียวต่อข้อมูลหนึ่งประเภท

## ภาพปกและการอนุมัติ

ภาพปกจะแสดงเมื่อ `cover_approved` หรือหัวคอลัมน์ภาษาไทยที่เทียบเท่าเป็น `TRUE`, `อนุมัติ` หรือ `อนุมัติแล้ว` เท่านั้น หากไม่มีคอลัมน์นี้ เว้นว่าง หรือใช้ค่าอื่น ระบบจะไม่ส่ง URL ภาพให้หน้าเว็บ โดยรายการหนังสือยังแสดงตามปกติ

รองรับภาพสองแบบ:

- **URL ภาพ HTTPS สาธารณะ:** เบราว์เซอร์โหลดภาพจาก URL โดยตรงหลังอนุมัติ
- **ไฟล์ภาพ Google Drive:** รองรับลิงก์ `/file/d/FILE_ID/view` และ `/open?id=FILE_ID` รวมถึงลิงก์จาก Google Form โดยเซิร์ฟเวอร์อ่านไฟล์ผ่าน Drive API แล้วส่งภาพผ่าน `/api/covers/BOOK_ID/` ไม่ส่งลิงก์ Drive หรือ credential ไปยังผู้ชม

### ตั้งค่าภาพจาก Drive ส่วนตัว

1. เปิด **Google Drive API** ใน Google Cloud project ที่ใช้ service account
2. แชร์ไฟล์หรือโฟลเดอร์ภาพให้ service account เป็น **Viewer**
3. ตั้ง General access เป็น **Restricted** และตรวจสิทธิ์ที่สืบทอดจากโฟลเดอร์ เว็บไซต์ไม่ได้เปลี่ยนสิทธิ์ Drive ให้เอง
4. ใส่ลิงก์ภาพในชีต แล้วอนุมัติผ่านคอลัมน์อนุมัติภาพ

API รองรับ JPEG, PNG, WebP, GIF และ AVIF ส่งภาพโดยไม่บันทึกลงดิสก์และตอบ `Cache-Control: no-store` ให้บริการเฉพาะภาพที่อนุมัติของหนังสือที่เผยแพร่ในแคตตาล็อก ไม่รับ Drive File ID โดยตรง

เมื่อยกเลิกการอนุมัติ คำขอภาพผ่าน API ครั้งถัดไปจะได้ 404 แต่ภาพที่ผู้ชมได้รับไปแล้วเรียกคืนไม่ได้ ไฟล์ Drive ยังคงเป็นส่วนตัว ส่วนภาพที่อนุมัติให้เว็บไซต์แสดงเป็นเนื้อหาที่ผู้ชมเข้าถึงได้ ควรจำกัดสิทธิ์แก้คอลัมน์อนุมัติให้เฉพาะผู้ดูแล และไม่ให้ผู้ส่ง Google Form กำหนดค่าอนุมัติเอง

## ช่องทางสั่งซื้อและติดต่อร้าน

กำหนดช่องทางจริงของร้านใน `.env.local` และบนโฮสต์:

```dotenv
SHOP_ORDER_URL=https://example.com/shop
SHOP_FACEBOOK_URL=https://www.facebook.com/your-shop
SHOP_LINE_URL=https://line.me/your-shop-link
SHOP_EMAIL=shop@example.com
```

เปลี่ยนค่าตัวอย่างเป็นข้อมูลจริง หรือเว้นว่างช่องทางที่ไม่ใช้ ลำดับการแสดงช่องทางสั่งซื้อคือ:

1. ใช้ `buy_url` ของหนังสือ หากเป็น HTTPS ที่ถูกต้อง
2. หากไม่มี ใช้ `SHOP_ORDER_URL`
3. หากไม่มีทั้งสองอย่าง แสดงช่องทางติดต่อที่ตั้งค่าไว้สำหรับเล่มที่พร้อมขาย

ช่องทางติดต่อปรากฏที่ท้ายเว็บด้วย ปุ่มอีเมลในรายละเอียดหนังสือเปิดแอปอีเมลพร้อมหัวข้อชื่อและรหัสหนังสือ โดยไม่ส่งข้อความอัตโนมัติ รายการเดโมไม่ใช้ช่องทางสั่งซื้อกลางหรือช่องทางติดต่อในหน้ารายละเอียด

## Environment variables

ดูค่าตั้งต้นทั้งหมดใน [.env.example](.env.example)

| ตัวแปร | การใช้งาน |
| --- | --- |
| `GOOGLE_SHEET_ID` | ID ของชีต; เว้นว่างเพื่อใช้โหมดเดโม |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | อีเมล service account; จำเป็นเมื่อเชื่อมชีต |
| `GOOGLE_PRIVATE_KEY` | Private key ของ service account; จำเป็นเมื่อเชื่อมชีต |
| `GOOGLE_SHEET_RANGE` | ช่วงข้อมูล; ค่าเริ่มต้น `Books!A1:Z1000` |
| `GOOGLE_SHEET_GID` | เลขแท็บสำหรับค้นหาชื่อแท็บอัตโนมัติ (ไม่บังคับ) |
| `SHOP_ORDER_URL` | ลิงก์ HTTPS สำหรับสั่งซื้อกลางของร้าน |
| `SHOP_FACEBOOK_URL` | ลิงก์ HTTPS ของ Facebook ร้าน |
| `SHOP_LINE_URL` | ลิงก์ HTTPS ของ LINE ร้าน |
| `SHOP_EMAIL` | อีเมลติดต่อร้าน |
| `NEXT_PUBLIC_BASE_PATH` | Prefix ของ URL เช่น `/bookshop`; เว้นว่างเมื่ออยู่ที่ root domain ต้องกำหนดก่อน build |

Credential ใช้เฉพาะฝั่งเซิร์ฟเวอร์ ห้ามเติม `NEXT_PUBLIC_` ให้ credential หรือ commit `.env.local` และไฟล์ JSON key

## Deploy

แอปต้องใช้โฮสต์ที่รัน **Node.js/Next.js ฝั่งเซิร์ฟเวอร์** ได้ เพราะอ่านชีตและส่งภาพ Drive ผ่าน API จึงไม่รองรับ GitHub Pages หรือ static export

1. ติดตั้ง dependency ด้วย `pnpm install --frozen-lockfile`
2. ตั้ง environment variables บนโฮสต์ตาม `.env.example` โดยให้ค่าชีต, credential และช่องทางร้านพร้อมใช้งานตอนรันเซิร์ฟเวอร์
3. หากใช้ `NEXT_PUBLIC_BASE_PATH` ให้กำหนดก่อน build และใช้ค่าเดียวกันตอนรัน
4. รัน `pnpm build` แล้ว `pnpm start`

ไฟล์ [.github/workflows/deploy-pages.yml](.github/workflows/deploy-pages.yml) แม้ยังใช้ชื่อเดิม แต่ทำหน้าที่ **ตรวจสอบแอปเท่านั้น** ไม่ได้ deploy โดยรันเมื่อ push ไป `main` / `master` หรือสั่งผ่าน `workflow_dispatch`

## โครงสร้างโปรเจกต์

```text
app/
  page.tsx                  หน้าแรกและการโหลดแคตตาล็อก
  layout.tsx                ภาษาและ metadata ของเว็บไซต์
  globals.css               รูปแบบและสีของเว็บไซต์
  api/covers/[bookId]/       API ส่งภาพปกจาก Google Drive
components/
  catalog.tsx               ค้นหา กรอง และแสดงรายละเอียดหนังสือ
  icons.tsx                 ไอคอนที่ใช้ในหน้าเว็บ
lib/
  catalog.ts                อ่าน Google Sheets และเตรียม URL ภาพ
  books.ts                  แปลงและตรวจข้อมูลหนังสือ
  contact.ts                เตรียมช่องทางติดต่อร้าน
  google-private-key.ts     จัดรูปแบบ private key
  demo.ts                   ข้อมูลหนังสือตัวอย่าง
  *.test.ts                 ชุดทดสอบ
data/books-template.csv    แม่แบบข้อมูลสำหรับนำเข้าชีต
public/images/              ภาพประกอบและภาพปกเดโม
docs/                      แนวทางและภาพต้นแบบงานออกแบบ
```

ปรับชื่อร้านและข้อความที่ `app/page.tsx` / `app/layout.tsx` ปรับรูปแบบที่ `app/globals.css` และปรับการแสดงรายการที่ `components/catalog.tsx` ภาพและหนังสือเดโมมีไว้สาธิต ไม่ใช่สินค้าจริง

## การแก้ปัญหา

| อาการ | สิ่งที่ควรตรวจ |
| --- | --- |
| ยังเห็นข้อมูลเดโม | กำหนด `GOOGLE_SHEET_ID` แล้วเริ่มเซิร์ฟเวอร์ใหม่ |
| โหลดหน้าแคตตาล็อกไม่ได้ | ดู server log ตรวจ ID ชีต, credential, การเปิด Sheets API และสิทธิ์ Viewer ของ service account |
| Sheets ตอบ HTTP 400 | ตรวจชื่อแท็บและช่วงข้อมูล หรือกำหนด `GOOGLE_SHEET_GID` คู่กับช่วงแบบ `A1:Z1000` |
| แจ้งหัวคอลัมน์ไม่ครบ | ตรวจหัวคอลัมน์บังคับทั้ง 5 และตำแหน่งหัวตารางใน 10 แถวแรกของช่วงที่อ่าน |
